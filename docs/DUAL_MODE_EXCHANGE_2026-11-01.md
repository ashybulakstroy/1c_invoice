и `WEB_CONFIRM_SUCCESS_UI.md`, предоставленные в R:/web. Уточнение пользователя:

- Страница: `GET /tasks/{task_id}/ui`, `App/web_server.py`; общий шаблон
  `App/web/index.html`, логика задания `App/web/app.js`, счёта `App/web/invoice.js`.
- Кнопка **существовала**: `#invoice-confirm`, текст «Подтвердить для 1С»,
  обработчик `confirmFor1C()` → `window.OCRTask.confirm(revision)` →
  `POST /tasks/{id}/confirm`, JSON `{revision}`. Но `refreshTaskConfirm()`
  принудительно скрывал кнопку. Через UI нажать её было нельзя.
- Backend confirm был работоспособен напрямую, но после прежнего уточнения
  пользователя проверка завершённости ограничивалась состоянием done.
- Обычный GET result сам вызывал фиксацию confirmed, даже без действия
  оператора. Поэтому старый confirmed не доказывал веб-подтверждение.
- Успешного блока под PDF не было. Старый toast предлагал нажать вторую
  кнопку в 1С, что не соответствует новому автоматическому сценарию.

## Реализованное поведение

| Состояние | GET result | GET result?allow_unconfirmed=1 |
|---|---|---|
| Фото нет / OCR выполняется / ошибка / обязательные данные неполны | 202, без items | 202, без items |
| Чек завершён, числа сверены, номенклатура заполнена, веб-подтверждения нет | 202 | 200 ready_unconfirmed, ocr_complete=true |
| Явное веб-подтверждение | 200 confirmed | 200 confirmed |
| Изменены исходные данные | 202 до нового подтверждения | новая версия завершённого черновика либо 202 |
| Применено в 1С | сохранённый неизменяемый результат | тот же результат |

Те же правила действуют для result.xml. Сохраняются task_id, database_id,
request_id, row_id, source/target/allowed_targets/selection_policy и коды
кандидатов. Несовпадение переданных идентификаторов → 409; чужой task_id → 404.
Параметр allow_unconfirmed не меняет правила доступа существующего API.

Черновик сохраняется как версия result-vN.json с checksum, но не получает
confirmed_at и не меняет состояние задания на confirmed. Повторный GET не
создаёт следующую версию. Подтверждение создаёт явную версию confirmed с
confirmation_origin=operator. Старые технические автоподтверждения без
этого признака не открывают автоматический импорт. Уже applied остаются
терминальными. Квитанция applied поддерживается и для вручную импортированного
черновика с проверкой версии и checksum.

Готовность обмена отделена от готовности **обучения**: не требуется отдельное
утверждение электронного чека и обучение связей. Требуются завершённая обработка,
контрольная сверка чисел, заполненные числовые поля, имя и единица товара 1С.
Существующие жёлтые предложения остаются в текущем счёте; GET не выбирает
новые товары по остаткам и не обучает связи.

## Интерфейс

Использована прежняя кнопка, теперь «Подтвердить и передать в 1С».
Текущий ручной выбор сохраняется перед confirm; сервер сверяет revision.
При недопустимых данных кнопка отключена, при ошибках показано сообщение
рядом со счётом. Ошибка сети, HTTP 202/409/500 не показывают успех.

После успешного HTTP 200 под видимым PDF появляется:

> Обработка завершена, данные будут переданы в 1С.
> Можете закрывать текущую веб-страницу.

Контейнер `#ocr-confirm-success`: role=status, aria-live=polite, tabindex=-1.
Выполнены scrollIntoView и focus с fallback; вкладка сама не закрывается.
После перезагрузки состояние восстанавливается с сервера. После правки
или несохранённого выбора успешный блок скрывается.

## Денежный контракт

Передача в JSON/XML без НДС, price_includes_vat=false внутри target и всех
allowed_targets, оба корневых флага цен также false. НДС остаётся отдельными
vat_rate/vat_amount/totals. Профиль 100 × 1870 = 187000; доставка 1 × 5000;
без НДС 192000, налог 30720, итог 222720. Строка НДС не номенклатура.
PDF по прежнему показывает цены с НДС. Исходный receipt и OCR не меняются.

## Ограничения и применение

Живой клиент/тестовая база 1С недоступны для управления в этой сессии:
реальный автоимпорт внутри 1С не подтверждён. Проверена Python-сторона,
готовая к опросу по заданному протоколу. Ручная команда 1С должна добавлять
allow_unconfirmed=1 и принимать ready_unconfirmed; автоматический опрос
не передаёт флаг и принимает только confirmed. В локальных BSL-заготовках
ещё нет всего нового поведения; они не заменяют установленное расширение.
Внешние Python/PYTHON_API_CONTRACT.md и примеры из задания не предоставлены
в R:/web; совместимость проверена с текущим работающим контрактом проекта.

ZIP содержит полные изменённые исходники с относительными путями и этот
отчёт, а не копию проекта. Применять из одной корневой папки поверх текущей
версии, сохраняя .env, data, web_outputs и локальное окружение. Перезапуск
одним процессом: `.venv/Scripts/python.exe -X utf8 -m App.web_server`.
Запуск сервера и .env не изменены. Сначала завершить активные OCR-задания.
