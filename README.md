## Запуск основного App

Команды из корня проекта (окружение `.venv` уже подготовлено):

```powershell
.venv\Scripts\python.exe -X utf8 -m App.web_server
```

Адрес и порт берутся из корневой `.env`: `OCR_WEB_HOST=0.0.0.0`,
`OCR_WEB_PORT=8016`. Сейчас страница доступна по http://127.0.0.1:8016.
Параметры CLI `--host` и `--port` явно переопределяют эти значения.
Для нового окружения: `py -3.14 -m venv .venv`,
затем `.venv\Scripts\python.exe -m pip install -r requirements-app-dev.txt`.
Для работы без инструментов проверки достаточно `requirements-app.txt`.
Нужны модель из [models/README.md](models/README.md) и справочники XLSX в
`data/reference/torgsoft_ref`. `python -m App` запускает пакетную оценку
геометрии, для веб-интерфейса используется именно `App.web_server`.

Проверки:

```powershell
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe -X utf8 -m pytest App/tests -q --continue-on-collection-errors
.venv\Scripts\python.exe -X utf8 tools/check_app_browser.py
```

Последняя команда требует работающий сервер по адресу из `.env` и установленный Edge;
создаёт тестовое задание по включённой фотографии, сохраняет скриншоты и отчёт
в `data/eval/startup_20261027`. Полный pytest пока имеет ошибки из-за
наследованных тестов со старыми фото, `eval_outputs` и `experiments`; детали в отчёте выше.
Эти старые данные и инструменты не требуются для запуска веб-приложения.
Проект начинает работу с пустой историей, новые примеры накапливаются при эксплуатации.
Старое окружение Python 3.12 сохранено в `.venv-py312-backup`; перенос каталога
обратно в `.venv` нужен для восстановления его прежних путей запуска.

## Предыдущая реализация — receipts_ocr / Фаза 1

Корневые `requirements.txt`, `requirements-dev.txt` относятся к этому прежнему
конвейеру; для основного `App/` используются отдельные файлы зависимостей выше.

Пайплайн Фазы 1: фото чека → геометрия → EasyOCR (CPU) → grid-таблица позиций
(имя/qty/price/sum) → сверка `Σ(qty×price)` против строки «Корытынды» (допуск 0.5).

- **Отчёт Фазы 1:** [`PHASE1_REPORT.md`](PHASE1_REPORT.md) — цифры, границы, изменения
- **Спека геометрии:** [`receipt_geometry_spec.md`](receipt_geometry_spec.md) — ТЗ,
  по которому построен S2-candidate-модуль
- **Батч-прогон:** `python -m receipts_ocr <папка_чека> --workers 4 -o data/eval/phase1_batchN.json`
- **Тесты:** `python -m unittest discover -s tests` (30 шт., stdlib unittest)
- **Корпус:** 29 фото чеков, развёрнутые данные в `data/eval/phase1_batch*.json`

Важно: консоль Windows cp1251 — не печатать Σ/DC/₽/кириллицу в stdout;
диагностику писать UTF-8-файлы (`tools/*.py` создают `data/eval/…`).
